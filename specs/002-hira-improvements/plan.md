## §3. Решение

**Куки (6, 10).** `secure` выводится из `WEB_ORIGIN`: https → `Secure`, http → нет. На https поведение то же, на локальном стенде заработает Safari. Отступление от Wiki/07, запишем туда и в журнал решений. Заодно: `grace` 30 секунд для только что заменённого токена (выдаём новый, сессии не отзываем), `navigator.locks` для обновления между вкладками, сбой сети не считается выходом.

**Перенос гостевого чата (12).** Новый `POST /api/v1/chats/claim-guest`: аккаунт доказан токеном, чат — httpOnly-cookie гостя. Одним запросом `chats` меняет владельца (`user_id` заполняется, `demo_session_id` очищается, этого требует `chats_owner_exactly_one`), в той же транзакции `search_logs.user_id` этого чата. Переносится только чат с сообщениями, пустой остаётся. Сообщения и показанные вакансии привязаны к чату и переезжают сами. Веб зовёт запрос сразу после регистрации и входа (В7), кладёт чат в список и открывает его. Если запрос упал, регистрация не отменяется, ведём на `/chat`. **Почему отдельный запрос, а не внутри `register`:** `ChatModule` уже зависит от `AuthModule`, обратная зависимость дала бы цикл модулей. Cookie гостя не стираем: счётчик гостевых реплик остаётся, поэтому выход из аккаунта не даёт новых 3 бесплатных. Факты в память из гостевых реплик задним числом не извлекаем, их и при обычной работе извлекают только в момент реплики. Работает только после правки cookie: в Safari иначе нечего переносить.

**Город и сайт (2, 11).** В подсказку каждой вакансии идут компания, город, формат, зарплата и название сайта. Город больше не теряется: неизвестный город без области записываем в новую группу `Другие города` (фильтр поиска по `l.city` работает сразу, `hard-filters.ts:81`). В выбор мест профиля эта группа не попадает. rabota.by берёт город из JSON-LD, если адреса нет. GSZ проверяем отдельно (3 из 5 без адреса; открытая страница уже отдаёт 404). Существующие вакансии исправит только повторная загрузка.

**Каталог (1).** Новый `CatalogStatsService` в core-api: всего, по областям, без города, remote, зарубежный remote, по сайтам. Считается по `ACTIVE`, кэш 5 минут. Блок идёт в подсказку каждой реплики, гостю тоже.

**Контекст (4).** В `GenerateRequest` появляется поле `facts`. Реплика получает: каталог; профиль и навыки; факты памяти; избранное; прошлые чаты (название, сводка, запросы, показанные вакансии), прошлые звонки; вакансии, показанные в этом разговоре. Блок ограничен размером (черновик 6000 знаков), новое важнее старого. **Почему блок, а не вызов инструментов моделью:** модель через OpenRouter на бесплатном тарифе, инструменты добавили бы ещё один круг запроса к и так медленному голосу. Объём данных маленький.

**Голос (3, 5).** Сервис [Speaches](https://github.com/speaches-ai/speaches) (MIT) отдельным контейнером на CPU: распознавание faster-whisper определяет язык сам, озвучка Piper. Перебивание: микрофон открыт весь звонок, начало речи ловит [`@ricky0123/vad-web`](https://www.npmjs.com/package/@ricky0123/vad-web) (ISC) в браузере. Звук Hira играет страница через `AudioContext`, поэтому его вычитает эхоподавление браузера. Начало речи во время ответа: звук стоп, поток отменён, фраза записывается. Озвучка идёт по предложениям, ещё до конца ответа. Женские голоса подбираем на слух при реализации: кандидаты `ru_RU-irina`, `en_US-amy`, `es_AR-daniela`, `de_DE-kerstin`, `fr_FR-siwis`. Лицензии голосов разные, у `irina` своя (RHVoice): проверяем каждую ([пример](https://huggingface.co/Trelis/piper-ru-ru-irina-medium)). Прежний [rhasspy/piper](https://github.com/rhasspy/piper) MIT, новый [piper1-gpl](https://github.com/OHF-Voice/piper1-gpl) GPL-3; сервис работает отдельным контейнером, но версию внутри образа тоже проверяем.

**Тарифы (8, 9).** План хранится в `users.plan`, значения и лимиты в одном месте (`PLAN_LIMITS` в `@hira/contracts`), его читают и сервер, и страница тарифов. Сервер сам проверяет лимиты, веб только показывает. Upgrade и смена плана выполняются сразу, без оплаты; метка плана и лимит обновляются без перезагрузки. Предложение по составу — §6 В2.

**Реактивность (7).** Маленькая шина `invalidate('favorites' | 'memory' | 'profile' | 'library' | 'chats' | 'account')`: после мутации экраны перечитывают свои данные. Плюс обновление при возврате на вкладку и `BroadcastChannel` между вкладками (сейчас ни того, ни другого нет). TanStack Query (MIT) решил бы то же, но потребовал бы переписать все экраны загрузки. Этого объёма задача не стоит.

Что исправляем:

| Где | Сейчас | Основание |
|---|---|---|
| Профиль: Save | 500, данные не сохраняются. Вероятная причина: `{ ...current, ...patch }` затирает поля значениями `undefined` из тела (`typeorm-profile.store.ts:37`) | Проверено (500), причина по коду |
| Избранное: снять в карточке вакансии | Кнопка меняется, но строка остаётся в списке до перезагрузки: список — локальное состояние страницы (`favorites-view.tsx:29`), кнопка пишет в другое хранилище (`favorite-toggle.tsx:57`) | По коду |
| Счётчик запросов после звонка | Не обновляется: `refreshQuota` есть только в чате (`use-chat-screen.ts:142`, в `call-view.tsx:276` нет) | По коду |
| Память после реплики | Панель чата перечитывает сразу на `done` (`chat-view.tsx:188`), а факты пишутся позже в фоне. Новый факт виден только после следующей реплики или перезагрузки | По коду |
| Память: открытая страница | Читает один раз при открытии (`memory-view.tsx:32`) | По коду |
| Другая вкладка | Ничего не узнаёт, в том числе о выходе | Проверено: поиск по `apps/web/src` пуст |
| Метка плана | Текст в коде (`profile-menu.tsx:27`) | По коду |

Что уже реактивно, не трогаем: заголовок и список чатов после реплики (проверено в Chromium), предложения профиля (`profile-view.tsx:39`).

| Название сайта | `source-label.ts` из `VacancySource` | код |
| Язык реплики | ответ распознавания; выбор в меню сильнее | клиент звонка |
| Токен доступа | zustand вкладки; refresh — только httpOnly cookie | core-api |
| Владелец чата | `chats.user_id` или `chats.demo_session_id` | `ChatStore`; смена только через `claimDemoChat` |

**API:**

- `PUT /api/v1/billing/plan` `{ plan }` → `CurrentUserDto`. Гость получает 401, веб ведёт его на регистрацию.
- `POST /api/v1/speech/transcribe` (audio, необязательный `language`) → `{ text, language }`. `POST /api/v1/speech/synthesize` `{ text, language }` → аудио. Только аккаунт с планом `call`.
- `POST /api/v1/chats/claim-guest` (токен аккаунта и cookie гостя) → `{ chat: ChatSummary | null }`. Повторный вызов и отсутствие чата дают `null`, не ошибку.
- `POST /calls/:id/turns` принимает `language`; остальные события те же.
- Сверх лимита: 403 `PLAN_LIMIT_REACHED`, в `details` `{ feature, requiredPlan }`.

**Миграция:** `users.plan` (по умолчанию `FREE`), строка `Другие города` в `locations`. **Порядок выкладки:** миграция, API, потом веб; всё поднимается одним `docker compose`. Новый контейнер скачает модели при первом старте.

## Отклонения от плана

- **`CatalogStats` получил `topCities`.** Вопрос «сколько в Москве» разбивка по областям не закрывает: неизвестные города лежат одной группой.
- **`CurrentUserDto` несёт `plan`, без `limits`.** Веб берёт лимиты из того же `PLAN_LIMITS` в contracts, второй источник не нужен.
- **Запрос `POST /calls/:id/turns` и подсказка получили правило голоса.** На звонке ответ просится короткий и без Markdown: длинный список вслух не слушается. В плане этого не было.
- **`knownVacancies` в `understand`.** Без него «найди похожую на вторую из избранного» понималось бы как новый поиск без опоры.
- **Голос Испании заменён.** `es_AR-daniela` в каталоге Speaches нет, `es_ES-sharvard` по высоте тона мужской. Взят `es_MX-claude-high` (ADR-047).
- **Whisper `base`, не `small`.** `small` читает фразу в 5 секунд за 10–14 с на этом Mac, `base` за 3–4 с, язык определяют оба.
- **`formatLocationLabel` больше не повторяет город:** было «Минск, Минск», стало «Минск». Это карточка вакансии, в задаче про город.
- **`speech-language.ts` остался.** Его читают диктовка и «Read aloud» чата, вне задачи. Звонок перешёл на новый `call-language.ts`.
- **Перенос чата: файл `enter-account.ts`.** Общий шаг после входа для обеих форм, в списке файлов не было.
- **Вакансий по 50 с сайта, а не по 300 (слово Daniel, 2026-10-31).** Всего до 200: на машине не хватает ресурсов на большую загрузку. `INGEST_LIMIT=50`.
