# 03. Источники данных и ingestion

Статус: черновик · Последнее обновление: 2026-10-03

---

## 1. Обзор источников

Решение принято: берём **шесть источников**. Это делает систему по-настоящему агрегатором и заметно усиливает главу «анализ предметной области», но добавляет две новые сущности в проект — **двуязычие корпуса** и **фриланс/проектную занятость**.

| # | Источник | Способ доступа | Язык | Приоритет | Объём (оценка) | Риск |
|---|---|---|---|---|---|---|
| 1 | **rabota.by** (HeadHunter BY) | Публичный REST API `api.hh.ru` | RU | Основной | 10 000+ по РБ | Низкий — официальный API |
| 2 | **ГСЗ** (gsz.gov.by) | HTML-парсинг | RU | Основной | десятки тысяч | Средний — нет API, но госресурс, данные открытые |
| 3 | **Хабр Карьера** | HTML-парсинг | RU | Основной | несколько тысяч, ИТ | Низкий — лояльная площадка, качественные структурированные данные |
| 4 | **praca.by** | HTML-парсинг | RU | Дополнительный | тысячи | Средний |
| 5 | **LinkedIn** | Публичные страницы вакансий | EN | Дополнительный | зависит от лимитов | **Высокий** — ToS запрещает автосбор, агрессивный антибот |
| 6 | **Indeed** | Публичные страницы / партнёрский фид | EN | Дополнительный | зависит от лимитов | **Высокий** — Cloudflare, антибот |

### 1.1 rabota.by — переход с HTML-парсинга на API

В курсовой 2026 использовался HTML-парсер по атрибутам `data-qa` — хрупкое решение, ломающееся при любом редизайне. rabota.by работает на платформе HeadHunter, у которой есть открытый документированный REST API (`https://api.hh.ru/vacancies`) с фильтрацией по региону, ключевым словам, опыту и формату работы.

В текст курсовой это ложится как «выявлена и устранена архитектурная уязвимость предыдущего решения — замена HTML-парсинга официальным API-коннектором».

### 1.2 Хабр Карьера — недооценённый источник

Стоит поднять в приоритете: данные там уже структурированы (навыки выделены тегами, грейд указан явно, зарплатная вилка чаще заполнена), площадка не воюет с парсерами, а ИТ-специализация хорошо ложится на целевую аудиторию выпускников. Для качества графа навыков это, вероятно, **самый полезный источник на единицу усилий**.

### 1.3 LinkedIn и Indeed — как снизить риск

Оба источника запрещают автоматизированный сбор в ToS и имеют серьёзный антибот. Раз решено их брать, риск надо не игнорировать, а инженерно ограничить:

| Мера | Смысл |
|---|---|
| Жёсткий троттлинг: 1 запрос в 10–15 с, суточный лимит | Не создаём нагрузку, не попадаем под поведенческие эвристики |
| Только публичные страницы вакансий, без авторизации | Не обходим технические средства защиты — важно юридически |
| Сбор заранее, а не во время демонстрации | **Ключевая мера.** На защите работает снимок базы; бан по IP не ломает показ |
| Данные кэшируются в БД, коннектор можно отключить конфигом | Отказ источника не ломает систему |
| Контрактные тесты коннектора на сохранённых HTML-фикстурах | Тесты проходят без сети |
| Раздел «ограничения и правовые аспекты» в работе | Честно описать, что источник взят с оговорками |

**Отдельно проверить:** у Indeed есть партнёрская программа Publisher/Job Sync с легальным фидом — если получится подключиться, это снимает риск полностью. Стоит потратить час на проверку доступности.

### 1.4 Что добавляют LinkedIn и Indeed содержательно

Два новых качества, которых нет у белорусских площадок:

1. **Фриланс и проектная занятость.** Это отдельный тип работы, и его надо смоделировать явно: новое значение `FREELANCE` / `PROJECT` в `EmploymentType`, поля «длительность проекта» и «ставка за час/день» вместо месячного оклада. Для выпускника без опыта фриланс — реальный вход в профессию, так что сценарий продуктово оправдан.
2. **Англоязычный сегмент и удалённая работа на зарубежные компании.** Это делает корпус двуязычным.

### 1.6 Indeed — нет легального read-API (Q29)

Исследование показало: **Job Sync API** — для ATS-партнёров, которые **публикуют** вакансии на Indeed (write-side). **Publisher XML/JSON feed** (legacy Job Search API) — deprecated (~2021–2023). **Publisher JS Plugin** — embed-only widget, данные не извлекаются.

**Для проекта:** Indeed-коннектор = HTML-парсинг публичных страниц с ограничениями (как LinkedIn) + фикстуры для тестов. **Приоритет 6** — первый кандидат на отсечение при нехватке времени. Подробнее — [09-open-questions.md](09-open-questions.md) Q29.

### 1.7 Географический охват (Q14)

| Уровень | Охват | Когда |
|---|---|---|
| **Минимум (обязательно)** | Вся **Республика Беларусь** | rabota.by (area=16 или без фильтра по региону), ГСЗ, praca.by, Хабр Карьера |
| **Расширение 1** | Европа + удалёнка | LinkedIn, Indeed — с флагом `isForeignRemote` |
| **Расширение 2** | США / весь мир | Если хватит ресурсов на ingestion и индексацию |

На защите формулировка: «основной фокус — рынок труда Республики Беларусь; система дополнительно агрегирует международные удалённые и фриланс-вакансии с явной маркировкой».

### 1.8 Зарубежные удалённые вакансии (Q30)

Включаем с флагом `is_foreign_remote = true` и фильтром в UI. Пользователь может скрыть/показать такие вакансии. Карточка помечается бейджем «Remote · International».

### 1.5 Двуязычие корпуса — следствия

Это не мелочь, а сквозное требование ко всей системе:

| Слой | Что меняется |
|---|---|
| Поиск, плотная ветвь | BGE-M3 обучен на кросс-язычный retrieval — русский запрос находит английскую вакансию без перевода. Дополнительный аргумент за выбор модели |
| Поиск, лексическая ветвь | Два частичных BM25-индекса (`russian` / `english`) по `vacancies.language`. Колонка — [04-data-model.md](04-data-model.md), ADR-030 |
| Граф навыков | Навык должен иметь алиасы на обоих языках: «Разработка на Python» и «Python development» ведут в один узел. Это **дополнительный аргумент за ESCO**, где английский — естественный pivot |
| Зарплаты | USD/EUR приводятся к BYN по курсу НБ РБ; для фриланса — отдельная логика для почасовых ставок |
| Генерация ответа | Язык ответа — язык реплики пользователя (ADR-028). В карточке — оригинальный текст вакансии |

Задача кросс-язычного сопоставления навыков — это ровно то, чем занимается работа «Multilingual Skill Extraction for Job Vacancy–Job Seeker Matching in Knowledge Graphs» (GenAIK 2025), так что подход опирается на литературу.

## 2. Архитектура ingestion

```
    cron (node-cron)
         │
         ▼
  ┌──────────────┐    ┌───────────────┐    ┌──────────────┐
  │  Connector   │───▶│  Normalizer   │───▶│  Deduplicator│
  │  (per source)│    │  → канон.форма│    │  (cross-src) │
  └──────────────┘    └───────────────┘    └──────┬───────┘
                                                   │
         ┌─────────────────────────────────────────┘
         ▼
  ┌──────────────┐    ┌───────────────┐    ┌──────────────┐
  │ SkillExtractor│──▶│ GraphLinker   │───▶│  Embedder    │
  │ (LLM)         │   │ (навыки→граф) │    │ (TEI)        │
  └──────────────┘    └───────────────┘    └──────┬───────┘
                                                   │
                                                   ▼
                                        ┌────────────────────┐
                                        │ PostgreSQL         │
                                        │ + ingestion_runs   │
                                        └────────────────────┘
```

### 2.1 Интерфейс коннектора

Каждый источник реализует один интерфейс — добавление нового источника не трогает остальной пайплайн:

```ts
interface VacancyConnector {
  readonly source: VacancySource;
  fetchList(params: FetchParams): AsyncIterable<RawVacancyRef>;
  fetchDetails(ref: RawVacancyRef): Promise<RawVacancy>;
  checkAlive(externalId: string): Promise<boolean>;
}
```

### 2.2 Нормализация

Сырые данные разных источников приводятся к единой канонической форме. Ключевые преобразования:

| Поле | Проблема | Решение |
|---|---|---|
| Зарплата | «от 1500 BYN», «1500–2000 руб.», «по договорённости», указана в USD | Парсинг в `salary_min`/`salary_max`/`currency`/`is_gross`, приведение к BYN по курсу НБ РБ на дату |
| Опыт | «Нет опыта», «От 1 года до 3 лет», «1-3 года» | Enum `SeniorityLevel`: `NO_EXPERIENCE`, `JUNIOR`, `MIDDLE`, `SENIOR`, `LEAD` |
| Формат работы | «Удалённо», «Можно удалённо», «Гибрид», «На месте работодателя» | Enum `WorkFormat`: `ONSITE`, `REMOTE`, `HYBRID` |
| Занятость | «Полная занятость», «Частичная», «Проектная» | Enum `EmploymentType` |
| Локация | «г. Минск», «Минск, ул. ...», «Гродненская обл.» | Нормализация к справочнику `locations` (регион + город) |
| Компания | «ООО "Рога и Копыта"», «Рога и Копыта», «ODO Roga i Kopyta» | Нормализация + слияние по УНП/нечёткому совпадению |
| Описание | HTML с разметкой, эмодзи, шаблонный «мы предлагаем печеньки» | Очистка HTML → Markdown, удаление boilerplate-блоков |
| Язык | RU у белорусских площадок, EN у LinkedIn/Indeed, встречается смешанный | Автоопределение, запись в `vacancies.language`; выбор конфигурации FTS |
| Фриланс | «$25/hr», «project-based, 3 months», «contract» | `EmploymentType.FREELANCE` / `PROJECT`, поля `rate_amount`, `rate_unit` (HOUR/DAY/PROJECT), `project_duration_days` |

Все enum'ы живут в `packages/contracts/src/common/enums/` — одно определение на весь монорепозиторий.

### 2.3 Дедупликация

Одна и та же вакансия часто висит на двух-трёх площадках. Каскад:

1. **Внутри источника:** уникальный ключ `(source, external_id)`.
2. **Между источниками:** кандидаты на дубликат ищутся по `(нормализованная компания, нормализованный title, город)`; подтверждение — косинусная близость эмбеддингов описаний выше 0.93 либо совпадение `simhash` описания.
3. При обнаружении дубля создаётся запись в `vacancy_duplicates`, одна вакансия помечается канонической, остальные скрываются из выдачи, но сохраняются (в карточке показываем «также опубликована на: …»).

Дедупликация между источниками — то, чего нет ни у одного портала, и заметный плюс в главе «функциональное тестирование».

### 2.4 Детекция изменений и закрытия

- `content_hash` = хеш от нормализованного (title + description + skills + условия). При изменении хеша инвалидируются эмбеддинги и извлечённые навыки, вакансия попадает в очередь на переобработку. **Это чинит баг курсовой 2026, где upsert обновлял текст, но оставлял старый вектор.**
- `last_seen_at` обновляется при каждом появлении вакансии в выдаче источника.
- Если вакансия не встречалась дольше `STALE_THRESHOLD_HOURS` (48 ч) — статус `EXPIRED`. Если источник явно отдаёт «архивная» — сразу `CLOSED`.
- Закрытые вакансии не удаляются: остаются для избранного и для истории чатов, но помечаются в UI.

## 3. Расписание

| Задача | Частота | Комментарий |
|---|---|---|
| Инкрементальный сбор, источники 1–4 (RU) | каждые 6 ч | только новое с прошлого прогона |
| Инкрементальный сбор, источники 5–6 (LinkedIn, Indeed) | раз в сутки, ночью, с суточным лимитом запросов | жёсткий троттлинг, отключаемо конфигом |
| Проверка живости активных вакансий | раз в сутки, 03:00 | батчами, с троттлингом |
| Извлечение навыков для необработанных | каждые 15 мин | очередь, батчи по 20 |
| Генерация эмбеддингов для новых/изменённых | каждые 15 мин | батчи по 32 |
| Пересчёт рёбер `RELATED_TO` и IDF навыков | раз в сутки, 04:00 | полный пересчёт по корпусу |
| Полная сверка (reconciliation) | раз в неделю | ловит пропуски инкрементальных прогонов |

Все задачи идемпотентны и переживают перезапуск: состояние в БД, а не в памяти процесса.

## 4. Соблюдение правил и этика

Отдельный подраздел, который стоит явно вынести и в текст курсовой:

- **robots.txt** проверяется и соблюдается для всех HTML-источников.
- **Rate limiting:** 1 запрос в 2–5 с для источников 1–4; 1 запрос в 10–15 с и суточный лимит для LinkedIn и Indeed. Экспоненциальный backoff при 429/503.
- Честный `User-Agent` с контактом, а не рандомизация под браузер.
- Приоритет официальных API над парсингом везде, где API есть; для Indeed проверяется возможность подключения к партнёрскому фиду.
- **Только публичные страницы.** Авторизация, обход капчи и технических средств защиты не применяются — это принципиальная граница, и её надо явно назвать в работе.
- **Персональные данные не собираются** — только объявления о вакансиях, которые являются публичной офертой. Резюме и профили соискателей с внешних площадок не трогаем.
- Хранится ссылка на оригинал; система позиционируется как агрегатор-навигатор, а не замена источнику.
- **Раздел «правовые аспекты и ограничения сбора данных»** выносится в текст курсовой отдельно: по LinkedIn и Indeed честно указывается, что сбор ведётся в исследовательских целях, в минимальном объёме, с публичных страниц, и что для промышленной эксплуатации потребовалось бы партнёрское соглашение. Это снимает вопрос комиссии заранее.

## 5. Наблюдаемость ingestion

Таблица `ingestion_runs` на каждый прогон: источник, тип задачи, время начала/конца, `fetched` / `created` / `updated` / `skipped` / `failed`, массив ошибок, статус. На основе неё — простая страница в админ-разделе (или хотя бы эндпоинт `GET /api/v1/admin/ingestion/runs`), которая на защите показывает, что база действительно живая и обновляется.
