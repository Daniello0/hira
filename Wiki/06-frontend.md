# 06. Фронтенд

Статус: черновик · Последнее обновление: 2026-10-31

## 2. Экраны

### 2.1 Чат (главный экран)

Раскладка как в ChatGPT: сайдбар, лента по центру (колонка 768 px), поле ввода внизу. Панель контекста — третья колонка, она открывается кнопкой в шапке и по умолчанию свёрнута ([ADR-042](10-decision-log.md)). На схеме она открыта.

Сайдбар: полный (340 px), рейл (52 px) или шторка на телефоне. В нём New chat, Library, Favorites, Call, Recents и меню профиля. Архивные чаты и настройки — на страницах `/settings/*`. Поиск по названиям чатов — `Cmd/Ctrl+K`, запрос `GET /chats?q=`.

Новый чат — `/chat`: приветствие и поле. Чат создаётся первым сообщением, а демо-сессия сразу попадает в свой единственный чат. Круглая кнопка в поле: пусто — вызов (`/call`), есть текст — отправка. Меню `+`: загрузка резюме, библиотека, Use memory, Show foreign remote. Под ответом — Copy и Read aloud, в поле — диктовка; всё работает в браузере, без бэкенда.

```
┌──────────┬──────────────────────────────┬─────────────┐
│ Sidebar  │  Лента диалога               │ Панель      │
│          │                              │ контекста   │
│ + Новый  │  ┌────────────────────────┐  │             │
│   чат    │  │ Пользователь: ...      │  │ Профиль:    │
│          │  └────────────────────────┘  │  Python     │
│ Поиск на │  ┌────────────────────────┐  │  SQL        │
│ Python   │  │ Ассистент:             │  │  Docker     │
│ Стажиров.│  │  Нашёл 8 вакансий...   │  │             │
│ QA-джуны │  │                        │  │ Фильтры:    │
│          │  │  [Карточка вакансии]   │  │  Junior     │
│ ──────── │  │   85 · Kubernetes ✓    │  │  Удалёнка   │
│ Избранное│  │   [объяснение ▾]       │  │  (смягчено) │
│ Профиль  │  │  [Карточка вакансии]   │  │             │
│ Память   │  └────────────────────────┘  │ Память: 3   │

```

Правая панель — важный элемент, даже свёрнутая: она делает прозрачным то, что обычно скрыто. Показывает, какое намерение извлекла модель, какие фильтры применились, какие смягчились и почему, какие факты памяти учтены. На защите это одна из главных демонстраций.

### 2.2 Карточка вакансии

Свёрнутое состояние: заголовок, компания, зарплата, локация, формат, интегральный скор, 3–4 совпавших навыка бейджами, кнопка «в избранное».

Развёрнутое — компонент `match-explanation.tsx`:

- горизонтальная столбчатая диаграмма по факторам (skill fit, semantic, lexical, experience, format, salary);
- три группы навыков разными цветами: совпавшие напрямую, совпавшие через граф (с подписью пути «Docker → Kubernetes»), недостающие;
- бейджи ветвей, которые нашли вакансию (лексическая / плотная / графовая);
- при наведении на навык — цитата из описания (`evidence_span`).

Навыки, совпавшие через граф, визуально отделены специально: это буквальная демонстрация того, что графовая ветвь работает и даёт то, чего не даёт векторный поиск.

### 2.3 Избранное (Q19)

**Отдельного «каталога вакансий» нет.** Просмотр сохранённых вакансий — через Favorites: LLM или пользователь добавляет в избранное из чата, затем список доступен на `/favorites`.

Сетка/список карточек, группировка по коллекциям, поиск по заметкам. Трекер статуса отклика — **не в scope** (Q15, диплом). Для закрытых вакансий — плашка «vacancy no longer active» со ссылкой на оригинал.

### 2.4 Профиль (Q7, Q22)

Форма профиля + редактор навыков. Резюме загружается в библиотеку (PDF), не отдельной формой на этом экране; modal навыков после разбора тот же.

Навыки — автодополнение по графу (`skills` + `skill_aliases`). Источник навыка: manual, resume, dialog (после подтверждения).

Страница — `/settings/profile`, старый адрес `/profile` редиректит.

**Предложения из диалога (Q22):** toast/modal «Add Python to your profile?» — accept → профиль, dismiss → игнор. Без автозаписи (ADR-008, ADR-021).

### 2.5 Память

Страница — `/settings/memory`, старый адрес `/memory` редиректит. Список того, что система запомнила: формулировка, тип (предпочтение / ограничение / факт / цель), уверенность, дата, ссылка на источник (чат, где записан факт, или подпись сессии вызова). Действия: закрепить, отредактировать, забыть, забыть всё.

Экран нужен не только продуктово — он закрывает вопрос комиссии «а вы не нарушаете приватность?». Ответ: пользователь видит и контролирует всё.

Переключатель **Cross-chat memory** на этом экране. Выключен — факты между чатами не читаются и не пишутся; текущий чат свою историю не теряет. Подробности — [07](07-auth-and-memory.md) §3.4 и [11-hira.md](11-hira.md).

### 2.6 Библиотека

Маршрут `/library`, только для вошедшего пользователя. Список файлов по видам: Resume, Preferences, Letters, Scripts, Notes.

- PDF — загрузка резюме. После разбора — тот же modal навыков, что раньше был на профиле. Файл остаётся в списке.
- md/txt — просмотр и правка в редакторе. Hira может предложить новый или изменённый текст из чата или вызова; сохранение только после подтверждения.
- Закрепление: резюме и предпочтения закреплены по умолчанию (всегда в контексте). Остальные подмешиваются по близости к реплике.

### 2.7 Вызов

Маршрут `/call`, пункт Call в сайдбаре и круглая кнопка в пустом поле ввода. Это не чат: нет ленты в sidebar, нет поля «написать сообщение» как главного действия.

Экран звонка: индикатор «listening / speaking», субтитры последних реплик, карточки вакансий — только если реплика запустила поиск. Озвучка и распознавание — в браузере. Транскрипт на сервере есть, в списке чатов его нет.

### 2.8 Billing / Prices (Q17)

Mock-страница `/settings/billing` (старый адрес `/billing` редиректит): карточки тарифов Free / Pro / Team, переключатель **monthly / yearly** (yearly со «скидкой»), CTA «Upgrade» без реальной оплаты. Демонстрирует продуктовое мышление на защите.

## 3. Стриминг

`chat.service.ts` читает SSE через `fetch` + `ReadableStream` (не `EventSource`, потому что нужен POST с телом и заголовком авторизации).

Порядок отрисовки:

1. `user-message` → сообщение сразу в ленте;
2. `intent` → правая панель заполняется, в ленте появляется индикатор «ищу…»;
3. `results` → карточки вакансий отрисовываются немедленно;
4. `token` → текст ответа дописывается посимвольно над карточками;
5. `done` → индикаторы снимаются.

Обрыв соединения: переподключение с указанием `lastEventId`; если ответ уже сохранён на сервере — подтягивается через `GET /messages`.

## 4. Состояние

- **Серверное состояние** (чаты, вакансии, избранное) — через Server Components и повторную валидацию; клиентский кэш минимальный.
- **Клиентское состояние** (черновик сообщения, открытые карточки, состояние стрима, тема, свёрнутый сайдбар) — Zustand, отдельный стор на фичу.
- Формы — React Hook Form + Yup, схемы валидации переиспользуют enum'ы из `packages/contracts`.

## 5. Оформление (Q18)

**Язык UI: English only.** Wiki и пояснительная записка — русский; интерфейс — английский. Ответ Hira — на языке реплики пользователя (ADR-028), не на языке кнопок.

**Тема: тёмная по умолчанию.** Палитра ChatGPT: чёрный фон, синий акцент. В настройках Appearance — System, Light, Dark; выбор хранится в браузере и применяется до первой отрисовки (ADR-042).

### Правило стилей: один источник (ADR-043)

**Цвет, размер, радиус, тень, шрифт записаны один раз — в `apps/web/src/styles/tokens.css`.** Компоненты только используют готовые классы (`bg-surface-card`, `rounded-bubble`, `w-sidebar`).

- **Нужен новый стиль — сначала токен в `src/styles/`**, потом класс в компоненте. Вписывать значение прямо в компонент нельзя.
- Стандартные шкалы Tailwind обнулены, поэтому `bg-white/10` или `max-w-md` просто не соберутся.
- Размер иконки — тоже токен: класс `size-icon-*`, а не проп `size={20}`.
- `src/styles/styles-ssot.test.ts` падает на hex, `rgb()`, произвольных значениях (`w-[34rem]`), старых токенах, размере иконки в `size` и цвете в `style`. Вне `src/styles` разрешена только ширина из данных (полоса совпадения).
- Цвет для манифеста и `theme-color` дублируется в `theme-colors.ts`, потому что там нельзя прочитать CSS-переменную. Равенство проверяет тот же тест.
- Тот же тест считает контраст текста в обеих темах: не ниже AA.

### Правило анимаций: везде и парами (ADR-043)

**Длительности, кривые и ключевые кадры записаны один раз — в `apps/web/src/styles/motion.css`.** Анимируется всё, что появляется, исчезает или переходит:

| Что | Как | Класс |
|---|---|---|
| Меню, селектор | открытие и закрытие 150 мс | `motion-menu` |
| Диалог | 250 мс вход, 200 мс выход | `motion-dialog`, `motion-scrim` |
| Шторка, панель вакансии | выезд 250 мс, уезд 200 мс | `motion-sheet-left`, `motion-sheet-right` |
| Сворачиваемый блок | высота в обе стороны 200 мс | `motion-collapsible`, `motion-chevron` |
| Подсказка | появление и исчезновение 150 мс | `motion-tooltip` |
| Сайдбар, панель контекста | ширина 200 мс | `motion-width`, `motion-swap` |
| Смена страницы | старая гаснет, новая появляется | View Transitions, `PageTransition` |
| Новое сообщение, строка, карточка | появление снизу | `motion-enter`, `motion-stagger` |
| Удаление и архивация строки, удаление навыка и города | уход влево, строка исчезает после ответа сервера | `motion-row`, `useLeaving` |
| Загрузка | бегущий блик, пульсация | `motion-shimmer`, `motion-skeleton` |

- **Открытие и закрытие — всегда пара.** Новый оверлей строится на `Dialog`, `Sheet`, `Menu` или `Select`: Radix держит элемент на экране, пока идёт анимация ухода. Поэтому в оверлеях — ключевые кадры, а не `transition`.
- Контент оверлея не исчезает раньше него: `useLastDefined` хранит последнее значение на время ухода.
- `prefers-reduced-motion: reduce` отключает движение глобально.

### Мобильная версия и PWA (ADR-044)

На телефоне сайдбар и панель контекста — шторки, поле ввода в две строки, высота экрана через `100dvh`, отступы safe-area, клавиатура сжимает страницу (`interactive-widget=resizes-content`). Приложение ставится на устройство: манифест, иконки, `public/sw.js`. Service worker кэширует только версионную статику и страницу `/offline`. Запросы к API и поток ответа идут мимо него, поэтому чаты офлайн не работают.

Доступность: семантическая разметка, фокус-ловушки в диалогах, `aria-live` для стримящегося ответа, контраст не ниже AA в обеих темах, управление меню с клавиатуры.

### Demo-режим (Q17)

Без регистрации: 1 чат, 3 запроса. При исчерпании — banner «Sign up for 20 queries/day» + ссылка на `/billing`. С регистрацией чатов сколько угодно; в sidebar счётчик запросов «12/20 queries today», не число чатов.

## 6. Почему не Streamlit (для главы «обоснование выбора»)

| Критерий | Streamlit (2026) | Next.js (2027) |
|---|---|---|
| Модель исполнения | скрипт перезапускается целиком на каждое действие | компонентная модель, точечные обновления |
| Многопользовательский режим | состояние в `session_state`, нет аккаунтов | полноценная аутентификация и изоляция данных |
| Маршрутизация | фактически одна страница | App Router, вложенные layout'ы, deep links |
| Стриминг | ограниченный | нативный SSE с посимвольной отрисовкой |
| Кастомизация UI | в рамках виджетов | полный контроль |
| SEO / шаринг | нет | SSR |

Streamlit — прототипный инструмент; переход на Next.js напрямую следует из требования «полноценное веб-приложение, а не чат-бот-демо».
