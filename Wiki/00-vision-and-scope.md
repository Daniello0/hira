# 00. Концепция и границы проекта

Статус: черновик · Последнее обновление: 2026-10-07

---

## 1. Тема и постановка

**Продукт:** **Hira** (Хайра) — имя веб-приложения и AI-помощника. Поверхности (библиотека, вызов, граница диплома) — [11-hira.md](11-hira.md).

**Тема, записанная у научного руководителя:** «Разработка веб-приложения на основе RAG-архитектуры для автоматизированного подбора вакансий».

**Альтернативная формулировка (согласована как запасной вариант, если потребуется уточнить акцент):** «Разработка микросервисного веб-приложения для автоматизированного подбора вакансий на основе RAG-архитектуры и графа знаний».

**Тема диплома** — [11-hira.md](11-hira.md) §5 (ADR-031).

Вторая точнее отражает две сильнейшие части работы — микросервисную декомпозицию и граф навыков, — но менять тему не обязательно: обе поддерживаются одним и тем же содержанием.

**Проблема.** Классические job-порталы (rabota.by, ГСЗ, LinkedIn) работают по схеме «жёсткий фасетный фильтр + лексический поиск по ключевым словам». Это ломается в трёх типичных ситуациях:

1. Соискатель не знает точного названия роли («хочу работать с данными в медицине» → в выдаче ничего, потому что в вакансиях написано «Data Analyst» и «биоинформатик»).
2. Навык называется иначе, чем в вакансии («k8s» vs «Kubernetes», «постгрес» vs «PostgreSQL»).
3. Запрос требует связывания фактов между документами («куда расти после джуна на Python», «какие вакансии близки к моему набору навыков, но требуют на один навык больше»).

**Решение.** Диалоговое веб-приложение, которое принимает свободный запрос на естественном языке, понимает намерение с учётом истории общения и профиля пользователя, и подбирает вакансии гибридным поиском по агрегированной базе из нескольких источников — с объяснением, почему каждая вакансия попала в выдачу.

## 2. Что изменилось по сравнению с курсовой 2026

Предыдущая работа (`Предыдущий_Курсач_2026/ai-job-finder-python`) — это Streamlit + FastAPI + PostgreSQL/pgvector + Sentence-BERT (`paraphrase-multilingual-MiniLM-L12-v2`, 384d) + Groq LLM для извлечения фильтров. Один источник данных (rabota.by, Гродненская область), один эндпоинт `GET /api/v1/search`, без авторизации, без истории, без тестов, без Docker.

| Аспект | Курсовая 2026 | Курсовая 2027 |
|---|---|---|
| Продукт | Чат-бот-демо, stateless | Веб-приложение **Hira** с аккаунтами |
| Архитектура | Монолит (FastAPI) + Streamlit | Микросервисы: web, core-api, retrieval, llm, ingestion |
| Стек | Python / FastAPI / Streamlit | TypeScript: NestJS (core), Next.js + Tailwind (web), Express (микросервисы) |
| Пользователь | Анонимный | Регистрация/вход, JWT, профиль |
| Диалог | Список сообщений в session_state, контекст не используется | Множественные чаты (как в ChatGPT/Gemini), контекст учитывается при поиске |
| Память | Нет | Трёхуровневая: окно + сводка чата + межчатовые факты; межчатовую память можно выключить |
| Файлы пользователя | Нет | Библиотека: PDF-резюме, md/txt; Hira читает и по подтверждению пишет md/txt |
| Голос | Нет | Вызов внутри приложения, без отдельного чата |
| Избранное | Нет | Сохранение вакансий, коллекции, заметки |
| Источники | rabota.by, ручной парсинг | шесть источников (rabota.by, ГСЗ, Хабр Карьера, praca.by, LinkedIn, Indeed), cron-обновление, дедупликация между источниками |
| Язык корпуса | Только русский | Двуязычный (RU + EN), кросс-язычный поиск |
| Типы занятости | Штатные вакансии | + фриланс и проектная занятость |
| Поиск | Bi-encoder (cosine) + эвристический доменный буст | Гибрид: BM25 + dense + графовое расширение → RRF → cross-encoder reranker |
| Языковой слой | Sentence-BERT 384d | Современный мультиязычный энкодер + граф навыков (см. [02](02-retrieval-layer.md)) |
| Объяснимость | Только `cosine_distance` в ответе | Пофакторная декомпозиция матчинга + список совпавших/недостающих навыков |
| Оценка | hit@1 / hit@5 на 16 запросах, вручную | nDCG@10, Recall@k, MRR, латентность p95, таблица абляций |
| Тесты | Отсутствуют | Vitest, TDD по конвенциям проекта |

**Чего в 2026 объективно не хватало (из аудита кода):**

- нет векторного индекса (HNSW) — полный скан таблицы;
- эмбеддинг вакансии строится по взвешенному шаблону, а эмбеддинг запроса — из сырого текста, отсюда асимметрия пространств;
- `ROLE_KEYWORDS_HARD_LOCK = True` — ILIKE-фильтр по ключевым словам может обнулить выдачу;
- при upsert вакансии эмбеддинг не инвалидируется → устаревшие векторы;
- синхронный `requests.post` к LLM внутри async-пайплайна блокирует event loop;
- внутренняя диагностика (применённые фильтры, шаги релаксации) считается, но не отдаётся в API;
- `DEFAULT_MIN_FILTERED_CANDIDATES = 1` — релаксация практически не срабатывает.

Всё это — готовый материал для параграфа «недостатки существующего решения» и одновременно список того, что чинится в 2027.

## 3. Целевая аудитория и сценарии

**Основная аудитория:** выпускники и студенты старших курсов ВУЗов Республики Беларусь, ищущие первую работу или стажировку.

**Ключевые сценарии (user stories):**

| ID | Сценарий |
|---|---|
| US-1 | Как соискатель, я регистрируюсь и заполняю профиль (навыки, специальность, ограничения), чтобы не повторять это в каждом запросе |
| US-2 | Как соискатель, я описываю свободным текстом, чего хочу, и получаю ранжированный список вакансий с объяснением релевантности |
| US-3 | Как соискатель, я уточняю запрос следующим сообщением («а можно удалёнку?»), и система понимает его в контексте предыдущего |
| US-4 | Как соискатель, я веду несколько параллельных чатов под разные направления поиска и переключаюсь между ними |
| US-5 | Как соискатель, я добавляю вакансии в избранное и возвращаюсь к ним позже |
| US-6 | Как соискатель, я вижу, каких навыков мне не хватает до интересной вакансии, и что стоит подтянуть |
| US-7 | Как соискатель, я получаю свежие вакансии — база обновляется автоматически, неактуальные помечаются закрытыми |
| US-8 | Как пользователь, я вижу и редактирую, что система обо мне «запомнила», и могу это удалить |
| US-9 | Как пользователь, я выключаю межчатовую память и продолжаю диалог только в рамках текущего чата |
| US-10 | Как соискатель, я храню у себя резюме (PDF) и текстовые файлы (предпочтения, письма, сценарии), а Hira их читает и по моей просьбе создаёт или правит md/txt |
| US-11 | Как пользователь, я звоню Hira внутри приложения — без нового чата — и быстро спрашиваю, уточняю или разговариваю |

Сценарии US-6 и US-8 — то, чего нет ни у одного из конкурентов-порталов, и именно они опираются на граф навыков и на память. Это основа блока «элементы научной новизны». US-9…US-11 — продуктовые поверхности Hira, не отдельное научное ядро.

## 4. Границы проекта (scope)

### Входит в курсовую

- Веб-приложение **Hira**: аутентификация, чаты, поиск, избранное (просмотр списком), профиль/память.
- **Межчатовая память** с выключателем на аккаунте (внутри чата контекст работает всегда).
- **Библиотека пользователя:** PDF-резюме, md/txt (предпочтения, письма, сценарии и пр.). Hira читает файлы и текст, создаёт и правит только md/txt.
- **Парсинг резюме** PDF → извлечение навыков → автозаполнение профиля + предложения добавить навыки из диалога. Файл остаётся в библиотеке.
- **Вызов:** разговор с Hira без чата, речью, внутри веб-приложения.
- Микросервисная декомпозиция с REST-контрактами и Swagger/OpenAPI.
- Агрегация вакансий из шести источников (с приоритетами — см. [09-open-questions.md](09-open-questions.md)) + cron-обновление.
- География: минимум **вся Республика Беларусь**; Европа/Америка/мир — по остаточному принципу ресурсов.
- Гибридный поисковый пайплайн с графом навыков и реранкингом.
- Демо-режим без регистрации (1 чат, 3 запроса). У зарегистрированного чаты не лимитированы числом, 20 поисковых запросов в день (ADR-029).
- Страница Billing/Prices (продуктовое мышление, mock-тарифы).
- UI: English only, dark theme default (blue–dark-blue–black). Ответ Hira — на языке реплики (ADR-028).
- Экспериментальная оценка: метрики качества поиска + абляции + латентность.
- Docker Compose (PostgreSQL, Redis, TEI, сервисы) для локального развёртывания.
- Юнит-тесты (Vitest) на бизнес-логику.

### Не входит (явно выносится в «направления дальнейшего развития» / диплом)

- Кабинет работодателя и публикация вакансий.
- **MCP и автоотклик** — диплом, тема в [11-hira.md](11-hira.md) §5 (ADR-031): либо фон на новые вакансии, либо отклик на вакансию, уже найденную в чате. Один и тот же инструмент.
- **Уведомления** о новых подходящих вакансиях (email/web-push).
- **Трекер статуса отклика** (APPLIED / INTERVIEW / …) — вместе с автооткликом, на диплом.
- Подтверждение email при регистрации.
- Админ-раздел в UI (достаточно эндпоинта + Swagger).
- Отдельный экран «каталог вакансий» с фасетными фильтрами (есть Favorites).
- Мобильное приложение, Telegram-бот, телефонная связь вне браузера. Голосовой вызов — это экран Hira, не отдельный клиент.
- Продакшн-деплой, CI/CD, горизонтальное масштабирование, Kubernetes.
- Дообучение (fine-tuning) собственных моделей.
- Полноценный A/B-тест на живых пользователях.
- Написание пояснительной записки — **не сейчас**, фокус на продукте.

## 5. Нефункциональные требования (предварительно)

Машина: MacBook Pro 15" (2019), Intel i9-9880H, 32 ГБ RAM, **inference только CPU**.

**Политика (ADR-022):** приоритет — **качество и новизна**, не скорость. Latency на локальной машине **не блокер**; на защите — обоснование аппаратным ограничением. Индексация **overnight**. Замеры: [`cpu-tei-benchmark/`](../cpu-tei-benchmark/).

| Требование | Значение | Как проверяется |
|---|---|---|
| **Качество поиска, nDCG@10** | **≥ 0.75** (приоритет №1) | [08](08-evaluation.md) |
| Прирост nDCG@10 vs 2026 | ≥ 0.10 абсолютных | абляции |
| Latency поиска (без LLM) | **~2.5 s+ OK**; до **15–30 s** допустимо | бенчмарк |
| Полный ответ в чате | до **1–2 min** допустимо | UX: spinner + SSE |
| Без reranker (деградация) | ~0.5–1 s | toggle |
| Корпус | ≥ 10 000 (цель 15 000) | БД |
| Индексация | overnight (~6–11 h) | ingestion |
| Отказ LLM | карточки без prose | интеграционный тест |
| Тесты `features/` | ≥ 70% | vitest |
| Свежесть данных | лаг ≤ 24 h | cron |

На GPU/сервере тот же пайплайн — ориентир **~400 ms** («направления развития»).

## 6. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| **Инференс на CPU не укладывается в удобную латентность** | Средняя | Среднее | Prod-реранкер — `bge-reranker-v2-m3` (ADR-022). На демо его можно отключить. Модель ~278M — только абляция |
| **Индексация корпуса занимает часы** | Высокая | Среднее | Малый снимок корпуса (1–2 тыс.) для отладки, полная индексация ночью, не более двух энкодеров в абляциях |
| LinkedIn / Indeed блокируют сбор (ToS + антибот) | Высокая | Среднее | Жёсткий троттлинг, только публичные страницы, **сбор заранее — на защите работает снимок базы**, коннектор отключаем конфигом, фикстуры для тестов |
| Вёрстка источника меняется → парсер ломается | Высокая (6 источников) | Высокое | Официальный API там, где есть; контрактные тесты на сохранённых HTML-фикстурах; статус в `ingestion_runs`; отказ одного источника не ломает систему |
| Машинный перевод меток ESCO даёт кривые русские термины | Средняя | Высокое | Ручная вычитка верхних уровней и 200 самых частотных навыков; пометка `ESCO_TRANSLATED` для отслеживания; алиасы из корпуса дополняют перевод |
| Ручная разметка бенчмарка съедает много времени | Высокая | Высокое | Сократить до 30 запросов, пул ограничить глубиной 8 на конфигурацию, размечать порциями |
| Бесплатные модели OpenRouter не поддерживают строгий JSON Schema | Средняя | Среднее | Выбрать модель с подтверждённой поддержкой structured output; запасной путь — парсинг с ретраями и валидацией |
| Граф навыков даёт прирост в пределах шума | Средняя | Высокое | Заранее заложить абляции; даже отрицательный результат валиден, если измерен с доверительными интервалами |
| Шесть источников + микросервисы раздувают объём работы | **Высокая** | Высокое | Monorepo, общий интерфейс коннектора (новый источник — один файл), общие типы, один Docker Compose. Приоритет источников: 1–3 обязательны, 4–6 по остаточному принципу |
| Стоимость LLM при извлечении навыков | Низкая | Среднее | OpenRouter (платные модели при необходимости), батчинг, кэш в Redis по `content_hash`, полный прогон один раз перед финальными замерами |
